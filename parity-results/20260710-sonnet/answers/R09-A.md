Not harmless — skip it. `hooks/hooks.json` is auto-discovered by convention; that's the whole reason we don't declare it. Adding `"hooks": "./hooks/hooks.json"` to `plugin.json` isn't inert metadata, it's a second declaration path, and most plugin systems don't dedup those — it double-registers every hook in that file. Concretely: each hook fires twice per event. For a hook with a purely informational side effect that's doubled (e.g. a logger writes two lines) that's just wasteful; for anything with a side effect that isn't idempotent (a git commit hook, a notifier, a counter/state mutation) it's an actual correctness bug, and it's the kind of thing that's easy to miss locally because a single manual trigger still "looks right" until you check for duplicates.

This is a known failure shape: two independent registration paths for the same rule/hook disagreeing or double-firing is exactly the class of bug that shows up as "works in testing, doubles in production" — the same pattern you get from any two enforcement points governing one behavior.

Tell the reviewer: the auto-load *is* the declaration — `hooks/hooks.json` is the manifest for hooks. If they want discoverability/"clarity," the fix is a comment or a README line pointing at the file, not a second registration path. Push back on the suggestion as written rather than take it.
