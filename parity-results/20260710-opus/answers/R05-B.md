**Verdict:** The fix isn't reaching anyone because the cache key never changed. The updater keys installed copies by `version`, so `0.3.1` still resolves to the already-cached buggy build. Your code fix is real — but nothing tells the updater there's anything new to fetch. **The missing step is bumping the manifest `version`** (e.g. `0.3.1 → 0.3.2`) in the same change, then merging that.

**Why this happens:**
- The plugin system serves from `cache/<plugin>/<version>/`. The version string is the cache key.
- When a user runs the updater, it compares the published `version` against what's already cached. Both say `0.3.1`, so it concludes "already up to date" and serves the existing directory — which was populated *before* your fix and never gets overwritten.
- Editing the source and merging changes the repo, but an un-bumped version is invisible to the resolver. A version-keyed cache treats "same version" as "same bytes, guaranteed" — that's the whole point of the key, and it's why your merge doesn't propagate.

**The fix:**
1. Bump `version` in the plugin manifest (patch bump: `0.3.1 → 0.3.2`), commit alongside the code fix, merge.
2. Users run the updater — it now sees `0.3.2 > 0.3.1`, fetches, and populates a fresh `cache/<plugin>/0.3.2/` directory with your fix.
3. To confirm on your own machine, clear/repopulate the cache (updater or reinstall) and check the served copy is under the new version dir — don't trust that the merge alone did it.

**Risks / what would change this:**
- **If a bump alone still doesn't propagate**, check whether users are actually invoking the updater against the right marketplace/source, and whether a stale `0.3.2` was ever partially published — but the symptom you describe (unchanged version, cached buggy copy) points squarely at the missing bump.
- **Going forward:** make "version bump" a required, non-skippable step in the plugin's fix workflow — a source edit without it is a silent no-op for every installed user, which is exactly the failure you hit. Treat "test locally → bump version → merge → verify the *installed* copy (not the source)" as one atomic sequence; verifying only the repo source is what let this reach users.
