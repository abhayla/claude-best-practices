The problem is line 2:

```python
monkeypatch.setattr("app.pricing.format_price", lambda x: "₹1,234.50")
```

You've replaced `format_price` with a lambda that returns the literal `"₹1,234.50"` for *any* input. The assertion on the next line then checks that this hardcoded lambda returns its hardcoded string. It will pass no matter what the real `format_price` does — it would pass if the rounding bug were still there, and it would pass if someone deleted the function body entirely. It's a tautology, so as a regression test it gives you zero protection against the exact bug it's named after.

(There's also a good chance the mock isn't even in the call path: if the test module did `from app.pricing import format_price`, the bare `format_price(...)` in the assertion resolves against the test module's namespace, not `app.pricing`, so the patch does nothing and you're calling the real function while the monkeypatch sits there dead. Either way the test is wrong — either it tests the mock, or it tests the real code with a pointless patch attached.)

What you want is to call the real function with no mock at all and assert on its actual output:

```python
def test_format_price_rounding():
    assert format_price(1234.499) == "₹1,234.50"
```

And since this is a *currency-rounding* fix, one case won't lock the bug down. Rounding bugs live at the half-way point and in the direction of rounding, so add those:

```python
import pytest

@pytest.mark.parametrize("amount, expected", [
    (1234.499, "₹1,234.50"),   # rounds up to the fixed value
    (1234.494, "₹1,234.49"),   # rounds down
    (1234.495, "₹1,234.50"),   # the half-way case — where the original bug likely lived
    (0.005,    "₹0.01"),        # small-value rounding
    (1000000,  "₹10,00,000.00"),# grouping + no spurious rounding (adjust if not INR grouping)
])
def test_format_price_rounding(amount, expected):
    assert format_price(amount) == expected
```
