The fix isn't reaching anyone because the cache is **version-keyed**, and you shipped your fix under a version number that already exists in everyone's cache.

## What's actually happening

The plugin system doesn't serve installed plugins from your repo — it serves them from `cache/<plugin>/<version>/`. When a user runs the updater, the updater's logic is essentially: "what version does the manifest advertise? `0.3.1`. Do I already have `0.3.1` cached? Yes. Nothing to do." It never re-fetches, because from its point of view there is no new version. Your corrected source and the buggy cached copy both live under the same `0.3.1` key, so the cache entry is a stale hit that never gets invalidated.

Merging your fix updated the *source of truth in the repo*, but the version field is the *only signal* the cache uses to decide whether a copy is out of date. You changed the code without changing the signal, so every installed copy is pinned to the old cached build forever.

## The missing step

**Bump the version in the manifest.** Change `version` from `0.3.1` to `0.3.2` (or whatever the correct SemVer increment is) in the same change that carries the fix, then merge/publish that.

Once the manifest advertises `0.3.2`:
- the updater sees a version it has never cached,
- it fetches the new build into `cache/<plugin>/0.3.2/`,
- and serves your fixed code from there.

The version bump is load-bearing, not cosmetic — it's the cache-invalidation key. A source edit without a bump is invisible to every installed copy by design.

## To recover the users already stuck

They're currently pinned to the cached `0.3.1`. After you publish the bumped version, a normal update will pull `0.3.2` and resolve it. If you need to confirm on a machine right now, either re-run the updater against the bumped manifest, or (as a one-off verification) clear/reinstall so the cache repopulates — but you shouldn't have to tell users to do that once the version is bumped; the updater will handle it.

## The habit to lock in

For any installed-plugin fix, treat it as a three-part change, never a code-only edit: **edit source → bump `version` → publish**. Test the edit locally first if you like, but the bump is what actually propagates it. It's worth adding a CI check that fails a plugin PR touching source files if the manifest `version` didn't change — that turns this into a caught mistake instead of a silent one.
