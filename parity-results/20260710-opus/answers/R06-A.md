Hey — I'm going to push back on the framing before writing anything, because writing this explainer as-worded would put a lie in our docs.

There is no "by design" reason slash commands get enhanced. The design says the exact opposite. Our config SSOT ships `enhance_slash_commands: false` with the comment "NEVER improve a /command — run it exactly as-is." A `/command` is a fixed invocation — there's nothing to strengthen, and silently rewriting it changes what the user explicitly asked to run. So if typed slash commands are going through the enhancement pipeline in prod, that's a **bug**, not a feature. The right artifact for the team is a heads-up that behavior diverged from spec, not a rationalization that makes the divergence sound intentional.

Here's what I'd actually send around instead:

---

**Heads-up: slash commands are being enhanced in prod — this is a defect, not intended behavior**

Our config SSOT sets `enhance_slash_commands: false` ("NEVER improve a /command — run it exactly as-is"). We're seeing typed slash commands run through the enhancement pipeline anyway. That's a contract violation — a `/command` must execute verbatim. Don't build on this behavior; it's getting fixed. If you have a workflow that currently relies on a slash command being rewritten, flag it now.

---

And separately, the things I'd chase to find the root cause (not guesses to publish, just where I'd look):

- **Is the flag being read at all?** Check whether the pipeline actually consults `enhance_slash_commands` before enhancing, or whether that config key is dead — defined in the SSOT but never wired into the gate.
- **Where's the slash-command detection?** Something has to classify the input as a `/command` before the flag can protect it. If detection runs *after* enhancement, or the prefix check is too strict (trailing space, leading whitespace, args after the command, plugin-namespaced `plugin:cmd` forms), the guard never fires.
- **Config precedence / defaults.** Confirm prod is loading the SSOT default and not a stale or overridden config where the flag flipped to `true` or is absent (and the code default is "enhance").
- **Layered guards.** In our setup the protection is enforced in more than one place (the deterministic prompt-gate hook that skips `/*` prompts, and the Stop-hook that exempts slash-command turns). If prod only has one layer deployed, or the hook that skips `/*` isn't installed there, commands leak into the pipeline.

Tell me which environment this is and I'll trace it to the specific gate — but I don't want to write "why it's by design," because it isn't, and documenting it that way would just cost us a debugging session later when someone trusts the doc.
