The problem: `"Smith, John & Sons",42` is CSV-quoted precisely because the name itself contains a comma. A naive split-on-comma will break it into three fields instead of two:

```
["\"Smith", " John & Sons\"", "42"]
```

Whatever you do with that (take field[0]/field[1], or field[0]/last) you get either a truncated name (`"Smith`) with the wrong seat count, or a garbled name with embedded quote characters. This isn't a hypothetical edge case — the partner's own sample data hits it on line 2 of 3, so it will fire in production immediately, not "someday."

The spec's plain-English description ("comma-separated") is underspecified — real CSV needs quote-handling for exactly this reason (RFC 4180: fields containing a comma must be quoted, and a quoted field's internal comma isn't a delimiter). Naive `split(',')` is not a CSV parser, it just looks like one until a name has a comma in it.

Fix: don't hand-roll this. Use your language's standard CSV reader (Python `csv.reader`, Node's `csv-parse`, etc.) instead of `.split(',')` — it already handles quoted fields, embedded commas, and (bonus) embedded quotes/newlines per RFC 4180 correctly. That's a small, low-risk change: swap the split call for a proper reader, keep the "two fields per record" validation you presumably already have.
